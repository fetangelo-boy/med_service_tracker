# МедОфис — учебный трекер задач и KPI

Статическое веб-приложение для небольшого медицинского офиса. Сделано по техническому заданию
`INFO/MedOffice_Tracker_TZ_v1_0.md`, но в упрощённой «учебной» версии:

- **авто-вход** — логин и пароль не требуются;
- **переключатель roles** в шапке — можно посмотреть интерфейс глазами директора, руководителя отдела и сотрудника;
- **без сервера и базы данных** — данные хранятся в `localStorage` браузера;
- **без сборки** — обычные HTML/CSS/JS, достаточно скопировать файлы на статический хостинг.

Все сотрудники, отделы и показатели в демо-данных вымышлены. Реальные персональные данные,
медицинская информация и доступы в проекте не используются.

## Структура

```
.
├── index.html          # каркас приложения
├── css/styles.css      # оформление, адаптив и стили печати
├── js/app.js           # логика, данные, ролевая модель, импорт/экспорт
└── INFO/               # исходное техническое задание (не используется приложением)
```

## Запуск локально

Откройте `index.html` в браузере — приложение заработает сразу.
Если хотите запустить через локальный сервер:

```bash
python -m http.server 3000
```

Затем откройте `http://localhost:3000`.

## Деплой на сервер

Это статические файлы: загрузите `index.html`, `css/` и `js/` в корень любого статического
хостинга (nginx, Apache, GitHub Pages, Netlify и т.д.). Никаких зависимостей и переменных окружения нет.

> Важно: в учебной версии данные хранятся **в браузере каждого пользователя**, а не на сервере.
> Для реальной совместной работы понадобится заменить `localStorage` на серверное хранилище
> (и вернуть авторизацию) — интерфейс при этом менять не придётся.

## Кто получает уведомления

Адресаты вычисляются по задаче, а не «всем подряд»:

- **автор задачи**, **ответственный**, **соисполнители/участники** и **все, кто уже писал в переписке**;
- **руководитель отдела** — по всем задачам своего отдела;
- **генеральный директор** — по задачам, где он автор/участник, по запросам решения руководства и по просрочкам;
- **инициатор запроса к руководству** — получает ответ/снятие флага;
- автор события уведомление не получает (он его только что создал).

Типы событий: `Комментарий`, `Назначение`, `Статус`, `Прогресс`, `Закрытие`, `Срок`, `Просрочено`, `Руководство`.
В уведомлении о комментарии показываются **автор и текст комментария**, есть кнопка «Открыть задачу»
и фильтры «Все / Комментарии / Сроки / Руководство». Сразу после отправки комментария во всплывающей
подсказке выводится число уведомлённых людей — так можно проверить доставку.

> Ограничение учебной версии: уведомления видны только в том браузере, где открыт соответствующий
> демо-пользователь. Общей доставки между устройствами нет, пока данные не перенесены на сервер.

## Цветовая гамма

Предложена с нуля, без брендбука:

- основной — бирюзовый `#0E7C86` (спокойный «медицинский» акцент);
- фон — холодный светло-серый `#F3F7F8`, карточки белые;
- статусы: зелёный `#1C9C62`, янтарный `#C9820B`, красный `#D24550`;
- отделы различаются мягкими оттенками бирюзового, синего и сиреневого.

## Управление данными

- **Сбросить демо-данные** — ссылка внизу бокового меню (или «Админка → Данные»).
- **Выгрузить данные (JSON)** — «Админка → Данные», можно сохранить резервную копию.
- Шаблон импорта скачивается в «Админке → Импорт CSV».

## Важное про роли

Разграничение прав в учебной версии работает в интерфейсе и в логике приложения (скрытие кнопок,
фильтрация отделов/задач/KPI, запрет изменений). Но поскольку данные лежат в браузере, это **не защита**
в понимании ТЗ §5 и §13: для продакшена права нужно проверять на сервере в каждом API.
